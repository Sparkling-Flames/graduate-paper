# 用重力方向识别另一种佩戴位置的上下楼

**不建议把这一方案作为双向迁移的主要改进。** 将动态加速度投影到重力方向后，裤袋训练、腰部验证的上下楼平均 F1 提高 8.52 个百分点；交换训练与验证数据集，四位裤袋验证者的上下楼平均 F1 都下降。站立 F1 在两方向仍接近零。模型只在源域训练及确定标准化参数，目标域标签仅用于最后计分。

## 两方向与各活动的结果

先计算每位目标验证者的逐类 F1，再等权平均各人，数值为百分比。坐和站均在实际验证集中，表中的零是模型实际得分。

| | 水平模长与无符号竖直分量 | 21.73 | 2.27 | 34.26 | 1.59 | 70.56 | 0.00 |
| | 水平模长与带符号竖直分量 | 23.26 | 0.92 | 30.91 | 9.90 | 74.56 | 0.00 |
| MotionSense 裤袋 → UCI 腰 | 原 13 维 | 21.87 | 2.22 | 0.00 | 45.04 | 62.10 | 0.00 |

带符号投影相对基线，上下楼平均 F1 在腰部验证者中有 6/8 人提高，在裤袋验证者中有 0/4 人提高。腰部目标的下楼得分也可以通过增加模长特征提高。模长对照与 13 维基线有 10 个重复通道；事后去掉重复项，仅增加模长的中位数、偏度和两个延迟的自相关，两域的整体 macro-F1 分别为 26.85%（目标裤袋）和 34.83%（目标腰部），后者的下楼 F1 为 71.30%。同维对照用于衡量特征扩充，去重结果可检查重复输入改变正则化强度的影响。

## 输入与协议

- 使用 [UCI HAR 官方训练集](https://archive.ics.uci.edu/dataset/240/human+activity+recognition+using+smartphones) 的惯性信号和 [MotionSense 作者发布的 DeviceMotion](https://github.com/mmalekzadeh/motion-sense)。两者均为 50 Hz、128 点窗、64 点步长。UCI 的重力估计为 total_acc − body_acc，MotionSense 使用发布的 gravity 与 userAcceleration。按时间点计算重力单位向量，用动态加速度与其点积得到带符号的竖直分量；减去竖直向量后取水平残差的模长。竖直符号沿各自发布的重力参考，传感器的信号处理实现也会随数据集改变。
- 基线为动态加速度和角速度的模长统计及窗平均重力方向的三个绝对分量。保留基线全部输入，对两条附加信号各取均值、标准差、第 10/50/90 百分位、相邻差分均方根、稳定化偏度及 12/24 点延迟自相关。比较两路模长、水平加无符号竖直、水平加带符号竖直三种同为 31 维的方案。另保存 21 维的去重模长对照。
- 与 [先前跨库实验](../activity_budget/README.md) 的无目标标签五分类基线共用原始读取器、按类平衡的 L2 逻辑回归及人员划分。UCI 为 13 位可训练、8 位开发验证（3、5、11、21、26、28、29、30），MotionSense 为 16 位可训练、4 位开发验证（2、5、14、19）。每个方向只使用源库训练人员拟合、目标库验证人员计分。UCI 验证共 2,312 窗，MotionSense 验证共 3,374 窗；每个模型评估的窗口相同。13 维基线的逐人逐类结果已和前次记录核对。
- 这是已有开发人员上的模型诊断。相邻窗有重叠，独立验证人数为 8 和 4。设备、人员、活动执行方式和预处理也随库改变，跨库方向差异无法单独归因于佩戴位置或重力估计。

## 最相近的工作

手机 HAR 已有工作明确用带符号竖直分量和水平模长表示加速度，并研究手机位于手上或口袋时的上楼、下楼、站立和行走。重力投影本身已有直接先例。本实验增加的是腰部和裤袋两个公开库互换训练、按人评分，并检验坐和站能否同时保持。[2020 年手机步态研究，式 3](https://www.mdpi.com/1424-8220/20/22/6559)

在已有 NumPy、pandas、SciPy、scikit-learn、threadpoolctl 及两份本地数据的环境中，从项目根目录运行 `python -B experiments/gravity_transfer/run.py`。[复跑代码](run.py) · [逐人逐类及两类楼梯与姿态平均分](scores.csv) · [逐人混淆矩阵计数](confusions.csv)
